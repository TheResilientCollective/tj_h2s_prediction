# Red-Tier (≥30 ppb) Recall Diagnosis — 2026-07-13

**Trigger:** the companion evaluation routine found 0% probability-call recall
on all 208 red-tier (≥30 ppb) rows in the validation store (2026-06-16 →
2026-07-11), confirmed by `skill_report.json` (`prob_recall_30_by_lead = 0.0`
at every lead for both variants). Worst case: NESTOR-BES 2026-06-27 08:00 UTC,
actual 218.8 ppb — the 1-hour *nowcast issued while the event was happening*
predicted 1.75 ppb with p30 < 1%.

## Scope: structural since the products path went live, not a break on date X

- Historical scorecards (`accuracy_reports/daily/...`) split into two regimes:
  the pre-2026-06-16 rows (site keys like `NESTOR__BES`) were generated by the
  2026-06-26 **hindcast backfill** of the legacy pipeline — recall ≈ 1.0, but
  hindcasts score with *measured* H2S lags, so they say nothing about live
  forecast skill. Live products-path rows (`NESTOR - BES`, from 2026-06-16)
  show red recall = 0 **from the first day**.
- The monthly 2026-04 scorecard (live legacy daily pipeline) had orange recall
  ≈ 0.43 — the legacy path saw events the products path misses.

## Root cause 1 (primary): the recursion seed is 7–36 h stale

`h2s_products` (and `station_forecasts` in the daily pipeline) seed the
autoregressive recursion from
`latest/tijuana/forecast_data/modeldata_h2s_nofill.parquet`. That file is
rewritten regularly, **but its newest rows end at the last complete day**
(observed on 2026-07-13 20:00 UTC: newest row 2026-07-12 00:00 PT — 37.5 h
old). The forecast met frame starts at the current hour, so product rows are
*labelled* nowcast/lead-1 while their `h2s_lag_*` / `h2s_rolling_*` features
describe yesterday. The model can never see an in-progress event.

**Proof the deployed models are fine:** replaying the 2026-06-27 event through
the production NESTOR-BES pickles with *true* lags:

| time (UTC) | actual | lean pred | lean p30 | production nowcast pred |
|---|---|---|---|---|
| 06-27 05:00 | 13.2 | 8.2 | 0.005 | 1.28 |
| 06-27 06:00 | 23.1 | 15.3 | 0.074 | 1.15 |
| 06-27 07:00 | 102.5 | 69.7 | **0.787** | 1.96 |
| 06-27 08:00 | 218.8 | 148.6 | **0.891** | 1.75 |
| 06-27 09:00 | 163.1 | 86.1 | **0.866** | 2.52 |

Across all 14 red-tier measured hours in the eval window, true-lag scoring
gives p30>0.5 recall **0.71** (0.93 @0.25) and regression ≥30 recall 0.79 — vs
0.0 in production.

**Fix (landed):** `h2s/forecasting/obs_freshness.py` tops the seed series up
from the near-real-time APCD feed
(`tijuana/sd_apcd_air/output/hs2_lastday.csv`, ~1–2 h latency), used by both
`h2s_products` and the daily `station_forecasts`. Live check at fix time: seed
gap 37.5 h → 1.5–2.5 h for all three stations. Failure of the feed degrades to
the old behaviour with a loud warning; a >3 h seed gap is logged per station
and surfaced in asset metadata (`seed_info`).

## Root cause 2: `wind_x_stable_atm` zero-filled at inference (Evidence variant)

`_engineer_forecast_features` never built `wind_x_stable_atm` (a trained
Evidence feature from `feature_builder.py`), so the products pipeline
silently zero-filled it every run. Likely the main driver of the Evidence
variant's near-zero ordinal skill (spearman_weighted 0.06 vs Lean 0.325) —
calm-night stability interactions are exactly the regime signal for events.

**Fix (landed):** the feature is now computed
(`wind_speed_10m * stable_atm`), and any remaining zero-fill logs a warning
naming the columns instead of passing silently.

## Root cause 3: the cascade "backup" read the same blind probabilities

Every cascade tier reads the model probabilities, so on the days the model was
blind the backup was blind too — cascade tier_1 stayed silent through the
2026-07-12 168.3 ppb onset.

**Fix (landed):** a raw-sensor **observation backstop**
(`evaluate_obs_backstop` in `cascade_alerts/cascade.py`): a tier fires when
measured H2S at NESTOR-BES within the last 3 h reaches its threshold,
independent of any model output, with its own per-tier debounce cells
(`tier_N_obs`). Observed ≥30/≥100 alerts also exist in `apcd_sensor_watch`;
the backstop covers the cascade's 5/10/30 tiers so a cascade run can never
pass an ongoing exceedance silently.

## Sensor QC note (eval item 5)

The 218.8 ppb reading is part of a coherent multi-hour ramp
(13 → 23 → 102 → 218 → 163 → 9.9 → 37), and SAN YSIDRO measured 33 ppb the
same night — consistent with a real event, not a one-sample fault. A March 13
2026 event reached 394 ppb (dispersion calibration doc). No QC exclusion
recommended; the existing ≤500 ppb cut stands.

## What this change does NOT fix — scoped follow-up plan

The seed fix restores nowcast/nearcast (leads 1–6) event visibility. The
forecast tier (leads 7–24) is genuine forecasting: by lead 7 all H2S lags are
the model's own predictions, and tail skill there is bounded by exogenous
drivers. Priorities, in order:

1. **Verify the fix (1 week).** Let `cascade_alerts_job` run, then
   `station_forecast_validation_rebuild_job`; check `prob_recall_30_by_lead`
   for nowcast/nearcast leads and the rolling 7d scorecard. Expect nowcast
   recall to move from 0 toward the walk-forward ~0.7–0.9 range.
2. **Fix the upstream feed** (`resilient_workflows` repo): make the
   `modeldata_h2s_nofill.parquet` builder include the current partial day.
   That also freshens the *flow* lags and removes reliance on the top-up.
3. **Pooled cross-station clf_30ppb** (existing plan:
   `docs/RETRAIN_STATION_CLF30PPB_BRIEF.md` §11,
   `experiments/underfitting_results/`): 435 pooled positives recover
   SAN YSIDRO / IB CIVIC CTR orange recall → re-enable them in
   `CLF_30PPB_STATIONS`. SAN YSIDRO had 40 of the 208 missed red rows and
   currently cannot emit p30 at all.
4. **Long-lead tail skill** (only after 1–3): reweight/oversample ≥10 and ≥30
   positives for the *forecast-tier* heads, or switch the regression to a
   heavy-tail loss (quantile/Tweedie); evaluate per-station tail calibration
   (NESTOR-BES max 218.8 vs SAN YSIDRO ~33). Judge by `prob_recall_p30` /
   event-level recall — Brier/ECE on p30 are dominated by negatives and were
   "good" (1–3%) throughout this total-blindness period.
5. **Cutoff review:** cascade tier_3 uses 0.5 on the forecast-window p30 while
   the daily pipeline's `PROB_30_ALERT` is 0.25. Once the validation store has
   post-fix data, tune the cascade cutoffs from measured recall/FAR curves.
